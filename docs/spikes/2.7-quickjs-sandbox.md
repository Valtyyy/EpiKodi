## Ordre d'application

1. Init QuickJS : `Runtime` + `Context::full`, `set_memory_limit` (64 Mo), `set_max_stack_size` (512 Ko), `set_interrupt_handler` (échéance), fonction `host.log`, échauffement (`JSON`, `Date`, `Math.random`) et `run_gc`.
2. `PR_SET_NO_NEW_PRIVS`, `PR_SET_PDEATHSIG(SIGKILL)`.
3. Landlock : tous les accès FS gérés, aucune règle (sauf `SPIKE_ALLOW_READ_DIR`), statut journalisé.
4. seccomp : liste de refus `socket`, `socketpair`, `connect` -> `EPERM`, action par défaut `Allow`.
5. `RLIMIT_AS` = 256 Mo (réglable).

## Protocole (une ligne JSON par message)

- Au démarrage : `{"event":"ready","sandbox":{"landlock":"FullyEnforced|PartiallyEnforced|NotEnforced|Skipped","seccomp":true,"rlimit_as_mb":256},"init_ms":..,"sandbox_ms":..}`
- Requête : `{"id":1,"method":"eval","params":{"code":"1+2","deadline_ms":200}}` ; réponse `{"id":1,"result":3}` ou `{"id":1,"error":{"code":-32000,"message":"..."}}`.
- `-32700` JSON invalide, `-32601` méthode inconnue. Sondes (spike uniquement) : `probe_socket`, `probe_socketpair`, `probe_open`.

## Test réel sans Landlock (Docker)

Image `node:22-alpine` locale (musl) ; le binaire glibc de l'hôte est lancé via le chargeur de l'hôte (`/lib/x86_64-linux-gnu` monté en lecture seule). Le profil `docker-noland-seccomp.json` renvoie `ENOSYS` (38) pour `landlock_create_ruleset/add_rule/restrict_self`. Conteneur éphémère (`--rm`, nom unique), aucun conteneur restant.

```sh
docker run --rm -i --security-opt seccomp=$PWD/docker-noland-seccomp.json \
  --entrypoint /hostlib/ld-linux-x86-64.so.2 -v /lib/x86_64-linux-gnu:/hostlib:ro \
  -v $PWD/target/debug/ext-host:/ext-host:ro node:22-alpine --library-path /hostlib /ext-host
```

Journal observé :

```
[ext-host] Landlock ABI detection failed errno=38
[ext-host] WARNING: Landlock status: NotEnforced (kernel lacks Landlock); relying on seccomp + QuickJS limits
[ext-host] seccomp installed (deny socket/socketpair/connect -> EPERM, default allow)
{"id":1,"result":{"ok":true,"ret":3}}                       <- /etc/passwd lisible : pas de Landlock
{"id":2,"result":{"errno":1,"name":"EPERM","ok":false}}     <- socket toujours bloqué
{"id":3,"result":3}                                          <- eval OK
```

Témoin dans le même environnement avec `seccomp=unconfined` : `FullyEnforced`, `EACCES`, `EPERM`.

## Incompatibilités et observations QuickJS

- Aucune incompatibilité bloquante avec le filtre seccomp (liste de refus) : `Date.now` (horloge), `Math.random`/allocation, `mmap`/`futex` fonctionnent après application.
- `RLIMIT_AS` : QuickJS alloue via `malloc`/`mmap` ; quand la limite AS est atteinte avant celle de QuickJS, l'échec de `malloc` devient `out of memory` JS (testé à 40 Mo vs 200 Mo), sans crash. Une limite plus basse que l'espace déjà mappé (4 Mo < VmPeak 6 Mo) ne gêne que les nouvelles projections : `[1,2].map(x=>x*2)` a fonctionné à 4, 8 et 16 Mo. Dans un vrai hôte multi-thread (tokio), `RLIMIT_AS` compte les piles de threads : prévoir une marge.
- Pas de `getrandom` problématique : il est autorisé (liste de refus) ; en liste blanche il faudrait l'autoriser, ainsi que `clock_gettime`, `futex`, `mmap/munmap/mremap/brk`, `read/write`, `exit_group`.
- Environnement JS nu : `typeof require/fetch/XMLHttpRequest/process/std/os` -> `undefined` (concaténation `undefinedx6`), `crypto` non défini.
- `Context::full` charge tous les intrinsèques ; en production préférer un contexte minimal.
- Non testé : filtre en liste blanche, threads, `connect` sur un socket hérité (le filtre le bloque aussi), `execve`, ptrace.

## Verdict

Faisable pour l'EPIC 10 : les trois lignes de défense du §7 fonctionnent ensemble, avec un coût négligeable (init ~1 ms, ~4 Mo de RSS). Sans Landlock, le filtre seccomp et les limites QuickJS restent actifs mais le système de fichiers est lisible : risque résiduel, à journaliser et à exposer à l'utilisateur.

## Recommandations EPIC 10

1. Passer le seccomp en liste blanche (en plus du refus réseau) : au minimum interdire `execve/execveat`, `ptrace`, `open*` après init, `bind`, `mount`, `io_uring_setup`. La liste de refus actuelle ne bloque que le réseau.
2. Appliquer Landlock avec `CompatLevel` explicite et exiger `FullyEnforced` en production (ou option « mode dégradé » visible dans l'UI).
3. Héritage de descripteurs : fermer tous les fd sauf stdin/stdout/stderr avant le sandbox (un fd de socket hérité reste utilisable pour `send/recv`).
4. Superviseur côté processus principal : heartbeat et SIGKILL ; l'échéance de l'interrupt handler ne couvre pas un blocage natif.
5. Ajouter un test CI du mode sans Landlock via Docker (profil fourni) et une matrice noyau.
6. Retirer les sondes `probe_*` hors du spike.
